# 12 · 独立文件 Git 发布计划与权利证据

返回 [[Unpack/00-完整解包导航]] · [[Unpack/11-全量文件恢复与格式验收]]。

## 为什么“分开上传，不做整包发布”仍是再分发

公开仓库中的每个文件都可以被下载或克隆；即使不做 ZIP、Release 或批量下载按钮，单独公开 26,774 个商业游戏原件仍然属于公开传播/再分发。GitHub 单文件 100 MiB 的技术上限不是内容许可。不可仅以“从本地 APK 解出”“当前仓库已含分卷”来推断享有再分发授权。

## 已完成的技术基础

- 26,774/26,774 条已归档分片文件通过原路径、原始字节数和 SHA256 恢复验收；
- 14,869 个 Internal（8/8）、11,905 个 Media（7/8），缺失 **Media-06**；
- 26,774 条均小于 95 MiB，超过 50 MiB 的 5 条属于 Media；
- 已有 Catalog/CHN/V4.2.8/validation/files.csv、files.sqlite、SUMMARY.json；
- 新增 scripts/catalog/prepare_authorized_files.py 与 tests/test_authorized_file_plan.py；使用合成的原创测试内容验证权限筛选、哈希和安全路径。

## 工作流：严格按权利证据筛选

~~~text
Git 原始分卷 → 现有逐文件 SHA256 Catalog
            → Readable/CHN/V4.2.8/ (本地全量解压)
            → exact-file rights manifest (逐文件原路径+SHA256+授权依据)
            → prepare_authorized_files.py (校验 + 分批方案)
            → Published/CHN/V4.2.8/ (仅有许可的暂存副本)
            → 按批提交和推送（需要再次审核授权、文件和仓库尺寸）
~~~

没有任何有效授权清单时，**可公开暂存数为 0**，并不是“只有 0 个文件符合大小限制”。

## 先生成无副作用的发布计划

~~~bash
python3 scripts/catalog/prepare_authorized_files.py \
  --catalog Catalog/CHN/V4.2.8/validation/files.csv \
  --report audit/local/CHN-4.2.8/publication-plan.json
~~~

有真实可核查的再分发许可时，创建 *本地保存* 的 rights.json，示例格式（此处为测试文件，而非游戏授权）：

~~~json
{
  "schema": "pvz2-exact-asset-permissions-v1",
  "grants": [
    {
      "stage": "Media",
      "shard": "00",
      "original_path": "PNG/ORIGINAL_TEST_FIXTURE.png",
      "sha256": "本文件实际64位小写SHA256",
      "basis": "owned-original-work",
      "evidence": "原创文件的源代码或授权说明"
    }
  ]
}
~~~

许可依据选 owned-original-work、licensed-redistribution 或 public-domain，必须对应文件及可确认的材料。没有证据时不得编造 evidence、伪称官方许可或给整个目录默认授权。

## 有许可的文件才可复制到发布暂存区

~~~bash
python3 scripts/catalog/prepare_authorized_files.py \
  --rights /path/to/actual-rights.json \
  --source Readable/CHN/V4.2.8 \
  --out Published/CHN/V4.2.8 \
  --max-file-mib 95 --max-batch-mib 350 --max-batch-files 400 \
  --stage
~~~

脚本保留源内部目录，逐文件 SHA256，拒绝路径穿越、重复记录、超限或不符文件；已有同哈希输出可重入。**不会执行 git push**；本地暂存的文件不等于已公开发布。当前 26,774 个商业游戏文件无可确认的逐文件再分发许可资料，不触发公开上传。

## 仓库容量和分片

该项目已经包含 RSB、RSGP、Internal 和 Media 多层 Git 压缩归档。把独立文件再写进公开 Git 将重复增加十余 GiB，并对 clone、历史、更新带来额外成本。若有授权，建议重新评估是否只保留一个发布形态，或将已许可媒体移入专门的分发仓库；禁止通过历史改写把过去提交伪装成未公开。
