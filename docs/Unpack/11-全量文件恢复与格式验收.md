# 11 · 分卷独立恢复 26,774 份文件与格式验收

返回 [[Unpack/00-完整解包导航]] · [[Unpack/10-独立素材清单与Git体积规则]] · [[Unpack/08-Git归档与完整性验收]]。

## 一定要区分三种完成状态

- **归档可恢复**：tar.zst.parts、manifest.json、SHA256 可重构正确的原始源目录。
- **文件级提取完整**：对每个原始独立文件重新计算 SHA256，并与 Catalog 的源文件清单逐条匹配。
- **格式与游戏运行已还原**：JSON 有效、PNG 像素可显示、PAM 动画能播放、WEM 音频可解码、POPFX 特效能正常绘制、波次能由运行时产生正确效果。这是多项独立验收，绝不能因 SHA256 正确就声称全部完成。

## 当前可恢复的范围

- Internal 8/8 个分片、14,869 份原始成员；
- Media 7/8 个分片、11,905 份派生文件；
- 合计 15 个 Git 分片、26,774 个文件记录。每一条大小都小于 95 MiB，已有 SHA256 真实源索引；
- Media/shard-06 **缺失正式 Git manifest**，不是零文件，不能计作已恢复成功；
- MediaSpecial 当前未归档，非 ASTC 的两个 PNG 的转换证据在 Actions Artifacts 和转换日志，仍需单独长期保存。

## 一键本地恢复命令（WSL/Linux）

先安装 Python 3.10+、GNU tar 与 zstd，并从 Git 完整检出对应 Unpack/ 的 15 个分片。注意：仓库对 Unpack/ 使用 .gitignore，Git 中已有的已跟踪文件仍需确认检出；稀疏检出不能只选择脚本。

在仓库根目录执行：

~~~bash
python3 scripts/catalog/export_all_local.py \
  --source Unpack/CHN/V4.2.8 \
  --catalog Catalog/CHN/V4.2.8 \
  --out Readable/CHN/V4.2.8 \
  --temporary /tmp \
  --dry-run

python3 scripts/catalog/export_all_local.py \
  --source Unpack/CHN/V4.2.8 \
  --catalog Catalog/CHN/V4.2.8 \
  --out Readable/CHN/V4.2.8 \
  --report audit/local/CHN-4.2.8/individual-export.json \
  --temporary /tmp
~~~

默认恢复两个阶段，按 shard 串行进行，避免一次性在临时目录堆满所有解压结果。每个 shard 先校验压缩档完整性并还原，再按原始 CSV 路径和源 SHA256 将文件复制到 Readable/CHN/V4.2.8/<Stage>/shard-XX/...。目标已有文件则检查 SHA256 后跳过复制，支持重试。若用 --require-all，缺失 Media-06 会使任务明确失败；默认记录 missing。

单独恢复并验收一个媒体分片：

~~~bash
python3 scripts/archive/restore_git_shard.py \
  Unpack/CHN/V4.2.8/Media/shard-00 \
  --out audit/local/recovered-media-00

python3 scripts/catalog/verify_materialized.py \
  --root audit/local/recovered-media-00 \
  --catalog Catalog/CHN/V4.2.8/shards/Media-00/files.csv \
  --out audit/local/verified-media-00
~~~

## 自动化真实验收

[Restore and validate all indexed individual files](https://github.com/969981/PVZ2_Resources/actions/workflows/pvz2-restore-verify-files.yml) 将 15 个分片独立运行：checkout 对应 Git 分卷 → zstd+tar 恢复真实文件 → 每文件 SHA256 对账 → 按真实扩展名做结构级审计 → 生成并上传仅含元数据的验收结果。

每个 shard 产出 files.csv 与 summary.json，合并任务在全部 15 分片通过后生成：

- Catalog/CHN/V4.2.8/validation/files.csv
- Catalog/CHN/V4.2.8/validation/files.sqlite
- Catalog/CHN/V4.2.8/validation/SUMMARY.json

合并环节要求 26,774 条记录、15 个唯一有效分片且 missing_shards=["Media-06"]，不会误报 8/8 媒体完成。

## 格式级验证的边界

| 格式 | 这轮实际检查 | 尚需单独验证 |
|---|---|---|
| JSON、PAM JSON、BNK JSON | 文本 JSON 语法解析、对象数量 | 所有游戏字段语义及运行时调用 |
| PNG | 文件签名、IHDR、合法宽高 | 像素流解码、alpha、贴图/图集正确性 |
| WEM | RIFF/RIFX + WAVE 文件头 | codec、PCM/WAV 转换、音效播放 |
| BNK | BKHD 文件头 | Wwise HIRC/STID 关系和音频事件 |
| PTX/PAM 原格式 | 文件完整 SHA256 | 针对格式独立的 1,522 PNG/3,847 PAM JSON 工具链 |
| POPFX/Lua/其他 | 原始完整字节、基本头部/文件格式分类 | POPFX 绘制、Lua 执行语义、未知格式 |
 
状态字段为 parsed、header-verified、checksum-only、unresolved、format-error。checksum-only 不是解包失败；也不能被算作格式完全解析成功。含内容不符合预期的文件应保留其 SHA 和失败原因，不得生成伪造的空输出。

## Git 提交与公开素材边界

本次默认提交脚本、Obsidian、原路径、SHA256、体积、格式审计数据库和报表。原始商业游戏的图片、音频等可按需在本地恢复；**小于 100 MiB 并不自动证明具有公开再分发授权**。原始文件在本地 Readable/ 下受 .gitignore 保护；已确认权利的项目素材可另外按大小、目录和批次管理发布，但不能在无授权证据时把完整第三方美术和音频直接推向公开仓库。
