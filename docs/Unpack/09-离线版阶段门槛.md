# 09 · 静态资源还原到完整离线运行，还差什么

返回 [[Unpack/00-完整解包导航]] · [[Offline/00-离线版总览]] · [[Offline/04-构建与验收]]。

> [!warning] 边界
> 已从 APK 提取的资源不能推出游戏已经离线可玩。客户端实际游戏逻辑、热更新数据、网络/存档状态、渲染、音频、关卡执行和设备验收都是独立工作。保留原始安装包及游戏文件，不对线上付费、账号、服务端权益作伪造。

## 必须依次关闭的门槛

| Gate | 完成定义 | 当前证据 |
|---|---|---|
| G0：原始数据完整可恢复 | APK SHA 固定；RSB/RSGP/Internal 全量、失败 0；独立 Git SHA256 | **已通过**：24/24 原始分片 |
| G1：静态素材转换 | 每个 PTX 可解 PNG，每个 PAM 有可用结构，BNK/WEM/POPFX/Lua 按格式审计 | **部分通过**：PTX/PAM 成功，音频和 POPFX/Lua 未完全闭合 |
| G2：真实素材可播放 | 图集切片/动画帧/特效在目标渲染器显示；声音 WAV 全量可播放并标明事件 | **未通过** |
| G3：游戏数据语义完整 | PlantType、ZombieType、PropertySheet、Projectile、Level、Wave/Action 和中文名来源外键完整，字段未猜测 | **部分通过** |
| G4：关卡逻辑动态验证 | 波次、动态事件、难度和掉落可按原游戏一致重现，38/16 未闭合 Wave 引用与 324 处差异已分类 | **未通过** |
| G5：客户端本地运行 | 真正完成启动、进入选关、加载资源、战斗、保存、退出重启、断网重复测试 | **未通过** |

不能跨越 G2～G5，直接宣称离线可玩。研究中的 M0 APK 静态审计是开发准备，不是成品 APK。

## 研究任务的优先顺序

### A · 波次和动态生成

- 阅读 [[Unpack/05-关卡与波次RTID]] 的 108,709 波次事件及 54 条未闭合引用；
- 对每种实际出现的 SpawnAction 记录物种外键、权重、数量、生成延时、行列、特殊条件、波次规则的原字段；
- 对 324 处 WaveCount 差异区分运行时修正器、合法数组变长、难度配置、配置不一致；
- 同版本运行时按相同关卡验证生成顺序、敌人类型、胜负条件，报告每个场景对应的源和输入。

### B · 素材实际播放

- 阅读 [[Unpack/02-PTX纹理与PNG]]、[[Unpack/03-PAM动画与图集]]：先完成最小 dino 图集→帧的可视化，再扩展；
- 阅读 [[Unpack/04-BNK-WEM与音频]]：按原 795+6,480 两类输入分别批量转码并回读 WAV；
- 阅读 [[Unpack/06-POPFX与Lua未识别格式]]：十个 POPFX 特效的静态/显示语义、43 个 Lua 的实际格式与依赖。

### C · 离线运行工程证据

- 参照 [[Offline/01-启动与网络依赖]] 找出哪些请求只是遥测、哪些请求真正影响内容获取/关卡加载；
- 参照 [[Offline/02-存档与本地状态]]，仅在本地、合法且可回退的数据副本上验证存档格式/状态；
- 在受控设备上完成飞行模式下从首次启动到完成关卡、保存、退出、重启的日志、截图、哈希和复现报告；
- 失败必须区分源资源缺失、引擎不支持、脚本逻辑缺失、启动网络依赖、设备兼容和版本不一致。

## 验收记录模板

每项功能一个实验编号，记录：
- 源版本（国服 4.2.8）、APK SHA256、资源 RSB/RSGP 路径；
- 完整解析命令、依赖及固定 commit；
- 输入物种/地图/关卡/模式/难度/随机种子（若实际存在）；
- 静态表中预期结果、运行时观察的实际结果、差异及证据；
- success、partial、unsupported、ambiguous、failed 五类状态；
- 可复现实验文件和 Git 提交或 Actions 运行链接。

## 禁止的错误验收

- 有 LevelDefinition JSON → 宣称所有关卡能玩；
- 有 PAM JSON → 宣称全部动画能播放；
- 提取 WEM → 宣称声音已经解码；
- 看到域名字符串 → 宣称真实请求已发生；
- 找到启动函数 → 宣称离线启动、存档及付费逻辑全正常；
- 服务器返回未知 → 填假值或静态替代并称“完整恢复”。
