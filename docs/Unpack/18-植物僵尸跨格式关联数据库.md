# 18 · 植物与僵尸的完整来源映射（静态数据层）

返回 [[Unpack/17-植物僵尸动画技能进阶道具装扮索引]]、[[Unpack/03-PAM动画与图集]]、[[Unpack/07-数据中文名与SQLite]]。

**目标**：不再只通过文件名检索，而以原始 PlantType / ZombieType 的「源文件 + 对象 index」为主键，把属性、等级、头像/装扮、技能候选、升级道具、资源组、已公开 PNG 与 PAM JSON 来源一同索引。每条关系保存来源与证据等级。

## 来源与可复现性

- 游戏版本：CHN 4.2.8；APK SHA256：\`64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4\`。
- 原始实体：\`Internal/shard-05/04_JSON/dynamic/Packages/PACKAGES/PLANTTYPES.json\` 与 \`ZOMBIETYPES.json\`。经 \`pvz2_chs428_gameplay_shard05.zip\` 的 SQLite 溯源读取（381 PlantType 源记录，1,265 ZombieType 源记录）。
- 属性/技能：\`PROPERTYSHEETS.json\`、\`SKILLTYPES.json\`、\`PROJECTILETYPES.json\`。
- 装扮/物品/进阶配置：\`PLANTNEWAVATARS.json\`、\`COLLECTABLETYPES.json\`、\`PVPUPGRADE.json\`、\`ARTIFACT*.json\`（检查哪些实际存在于原始索引）。
- 资源和图集：\`pvz2_chs428_resource_catalog.zip\` 的原始资源 group_id，\`semantic_assets/asset_paths.csv\` 的 1,520 PNG、3,847 PAM_JSON / 3,847 PAM 来源清单。
- 中文：\`pvz2_chs428_localized_entities.zip\` 的 \`zh_cn_name\`，植物/僵尸 TypeName 映射只表示候选字符串关系，不直接当游戏内权威名称。
- 真实运行工作流：[Build verified PvZ2 plant zombie type crosswalk](https://github.com/969981/PVZ2_Resources/actions/workflows/pvz2-entity-crosswalk.yml)。该任务先按 manifest 和 SHA256 恢复 Internal-05 的原生 JSON，再建立数据表，测试通过后才写入 master。

## 生成的数据库

[Catalog/CHN/V4.2.8/entity_map](https://github.com/969981/PVZ2_Resources/tree/master/Catalog/CHN/V4.2.8/entity_map) 预期包含：

| 文件 | 内容 | 关系性质 |
|---|---|---|
| \`entities.csv\` | 每个 PlantType / ZombieType 的原生对象主键、TypeName、中文候选、PopAnim、Properties、ResourceGroups、Avatars、图标/碎片字段 | **直接源值** |
| \`links.csv\` | Properties / 显式技能、投射物 RTID 到源对象 | 精确 alias 才归为静态可匹配，其余 unresolved/ambiguous |
| \`level_rows.csv\` | 经源 alias 映射得到的 PlantLevelStats、PlantStats、ZombieLevelStats、Hitpoints、Speed 等原始字段及数组序号 | **原始值**，不是实际战斗公式 |
| \`avatars.csv\` | 植物每一个原生 Avatars 数组元素及原引用 | 直接数组成员，不等于可穿戴装扮总量 |
| \`ancillary.csv\` | Collectable/Accessory/Avatar/Artifact/Upgrade 相关真实 objclass 和原始字段名 | 源对象存在性 |
| \`ancillary_links.csv\` | 装扮、配件、物品中实际引用植物/僵尸的候选连接 | 可能只由原始字段/RTID 名称建立，需验证语义 |
| \`resource_groups.csv\` | \`PlantResourceGroups\` / \`ResourceGroups\` 到 resources RTON group_id 的显式对应及歧义 | 源标识关系 |
| \`assets.csv\` | PNG/PAM JSON 的具体 shard、原路径、SHA256、可点击 GitHub PNG URL 和与实体关联的证据等级 | **资源组名或文件名候选，不是已闭合 atlas image_id** |
| \`skill_records.csv\` | 所有 SkillPropertySheet 原始 skill 名、描述和图标引用 | 技能静态记录 |
| \`pvz2_chs428_entities.sqlite\` | 上述九张表、索引、完整性自检 | 按植物/僵尸可查 |
| \`SUMMARY.json\` | 分母、每类匹配/缺失/歧义统计、源 JSON 的 SHA256 证据 | 验收结果 |

## 证据级别（绝不能省略）

- \`source-PlantType\` / \`source-ZombieType\`：原始对象存在，非独立物种总数。
- \`exact-alias-source-reference\`：真正对照原始 alias 标识符匹配 PropertySheet；若多个相同 alias 必须记 \`ambiguous-alias\`。
- \`exact-resource-group-id\`：资源组 ID 在 resource RTON 里存在；不自动验证 image_id。
- \`resource-group-name-candidate\`：关联到同名图片/动画组，只是候选，不能当像素级外键。
- \`filename-exact-normalized-candidate\`：仅名字候选，可信度更低。
- \`unresolved\`：原始引用没有找到明确目标；保留。
- \`source-exact-property-alias-no-runtime-formula\`：属性表原始等级数值，不包含运行时难度缩放、进阶实际规则。
- Avatar 原始数组不代表“装扮已装备”。图片与技能、道具的一对一关系需要后续 \`resource_id\`、动画 image-name、原生代码及实机验证。

## 本地复现

\`\`\`bash
git pull origin master
sudo apt-get install -y zstd

python3 scripts/archive/restore_git_shard.py \
  Unpack/CHN/V4.2.8/Internal/shard-05 \
  --out /tmp/pvz2-internal05

python3 scripts/catalog/build_entity_crosswalk.py \
  --repo-root . \
  --raw-root /tmp/pvz2-internal05 \
  --out Catalog/CHN/V4.2.8/entity_map

python3 scripts/catalog/render_entity_obsidian.py \
  --db Catalog/CHN/V4.2.8/entity_map/pvz2_chs428_entities.sqlite \
  --docs docs/Entities/CHN/V4.2.8
\`\`\`

命令必须实际通过，才可认为数据表生成成功。默认验证源包 SHA256、选定原始 JSON 的哈希以及 SQLite integrity_check。文件缺失会明确报错，不生成空的“全量成功”结果。

## SQLite 查询例子

\`\`\`sql
-- 豌豆射手真实 PlantType 配置，可以有多条不同来源记录
SELECT entity_id,type_name,chinese_candidate,source_file,object_index,
       property_ref_json,popanim_json,avatar_items
FROM entities WHERE kind='plant' AND lower(type_name)='peashooter';

-- 查看植物原始等级、强度字段（只展示已按精确 alias 闭合的行）
SELECT e.type_name,l.field,l.ordinal,l.raw_value_json,l.status
FROM entities e JOIN level_rows l ON e.entity_id=l.entity_id
WHERE e.kind='plant' AND lower(e.type_name)='peashooter'
ORDER BY l.field,CAST(l.ordinal AS INTEGER);

-- 原始装扮引用/素材图集（来源状态必读）
SELECT e.type_name,a.format,a.source_path,a.published_png_path,a.association_status
FROM entities e JOIN assets a ON e.entity_id=a.entity_id
WHERE e.kind='plant' AND lower(e.type_name)='peashooter';

-- 所有 TypeName=dark_basic 的僵尸配置（不同关卡不能自动合并）
SELECT entity_id,source_file,object_index,property_ref_json
FROM entities WHERE kind='zombie' AND lower(type_name)='dark_basic';
\`\`\`

## 尚不能宣称完成的事情

1. 逐帧 PAM 真实渲染、每个 ImageID→Atlas 像素裁剪区域外键。
2. 每个 Avatar 的实际装配部位、等级限制、技能加成最终生效值。
3. 所有植物、僵尸的原始 PropertySheet / SkillSheet 真实来源闭合比例，以工作流 SUMMARY 为准。
4. 因地形、关卡、强化/进阶和难度造成的运行时数值变化。
5. 数据库中没有的远程下载、动态活动皮肤资源、未在 APK 内的素材。

这些都应按已验证、候选、未解析分别记录，不应按表行数直接宣传完成。
