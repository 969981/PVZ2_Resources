# PVZ2 国服 4.2.8：离线单机改造进度与验收台账

> [!warning] 当前状态：未实现原版离线畅玩
> 截至 2026-11-07，已在真实原版 APK 上确认断网完成首次解压、到达拓维手机登录屏幕、部分 JNI 调用顺序与原生函数入口候选；**仍没有成功进入主菜单、打完第一关或证明原生游戏读档**。仓库内的 LocalProfileStore 仅作为独立原创组件通过单元测试，**不是原游戏存档**。

## 目标与验收边界

要求是**完全无网络依赖的独立单人模式**，保留原版战斗与本地关卡资源：全新安装 → 接受隐私条款 → 本地玩家会话 → 游戏主菜单 → 选第一关 → 战斗/结算 → 退出进程 → 断网冷启动 → 仍有相同进度与解锁状态。这里**不包含**伪造在线短信、冒用账号、在线付费权益或重建真实服务器。

## 原版游戏实际观测

首次运行飞行模式下，在明确确认隐私条款画面后选择“同意”。EA 启动页面 → 本地解压文件 1/6 → 大约 600 秒出现拓维登录界面：手机号、短信验证码和账号密码登录。900 秒仍显示登录。此前日志采样出现 DNS 错误，但不能据此确定关卡检查的代码地址。

**不能**把以下项目视为原版可离线游玩：

- Github Actions 构建/单元测试成功；
- 全量 RSB 解包或 6 个 DEX 反编译成功；
- 静态 JNI 注册表找到函数地址；
- 自建的 `LocalProfileStore` 写入成功；
- 将所有 HTTP 请求改成成功响应或忽略错误。

## 原生登录链：已证明到哪一步？

静态 `TWPurchase.java` 反编译记录：

```text
TWPurchase.run()
  → Native_SDKInitStart
  → TwOfflineSDK.init
  → onResponse
  → Native_SDKInitEnd
  → Native_SDKLoginStart
  → TwOfflineSDK.login
  → onResponse
  → Native_SDKLoginEnd    # 5 个静态调用位置：行 169、173、177、180、185
```

真实 Java 声明 `Native_SDKLoginEnd(long, int, String): void`。五处调用都传 3 个参数，已按真实源码确认第二参数依次为 **0、1、1、1、0**，第一参数为 `TWPurchase.this.mNativeDriverPtr`、第三参数为 **`loginResultBean.token`**。这证明 Java 传入的是登录令牌字段而不是直接传入 `userId`；**仍未证明原生如何使用令牌，0/1 的成功/失败含义也未验收**。详见 [[17-登录结束回调分支结构]]。

同 APK 的 ELF 结构扫描结果：

| JNI 方法 | 原生入口候选 RVA | 注册表项 RVA |
| --- | --- | --- |
| `Native_SDKInitStart` | `0x4A9B1B0` | `0x5E6C910` |
| `Native_SDKInitEnd` | `0x4A9B284` | `0x5E6C928` |
| `Native_SDKLoginStart` | `0x4A9B488` | `0x5E6C940` |
| `Native_SDKLoginEnd` | `0x4A9B678` | `0x5E6C958` |

上述为 24 字节 JNI 表连续记录、相对重定位、JNI 方法签名与可执行段指针共同核验的**函数地址候选**。不代表已经通过 GDB 确认它们实际执行，也不是可立即替换的登录分支。

## 下一阶段的执行门槛

1. **函数语义**：同 SHA ARM64 `libSrc.so` 在 Ghidra 中检查 `0x4A9B678` 函数指令、形参读写、返回/状态分支和调用者，并与 Java 的五处回调分支对上。必须保留真实观察与推断区别。
2. **本地会话合同**：确定引擎使用的玩家标识类型、初始化时序、存档路径与来源字段；单机 ID 不冒充服务端账号，不参与任何在线付费权益。
3. **最小可回滚集成**：把独立本地会话接入已确认的 SDK/Native 桥接点，不动支付/广告以外的游戏引擎结构；只在个人测试环境生成 APK，不提交商业游戏素材。
4. **关卡与读档**：原版主菜单截图 → 第一关进入 → 胜利结算 → 退出 → 冷启动同一进度的真实截图与本地文件前后差异。每一步单独测试，未验证项保持 `未验收`。
