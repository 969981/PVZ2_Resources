# 离线游戏完整链路验收规范

> [!important] 测试必须用真实原版引擎或基于真实原版制作的隔离测试版本
> `LocalProfileStore` 的单元测试、合成关卡 ID、模拟 UI 或自造回调，**不能替代真实打关卡测试**。任何证据都要绑定 APK SHA256、ABI、运行环境、测试版本与操作序列。

## 前置条件

- 原始基线：`PVZ2_4.2.8.apk`，SHA256 `64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4`。
- 测试环境：新的 Android 11 虚拟设备、无真实手机号和实名账户、飞行模式始终 `1`、测试过程不连接网络。
- 每个改动版必须保留 SHA256、变更源码对应的 Git commit、被改 DEX/SO 的原字节校验与回滚方法。仅供个人研究使用，不公开上传修改后的游戏 APK、原始素材或商业资源。
- 飞行模式检查指令：`adb shell settings get global airplane_mode_on`；仅输出 `1` 才进入下一阶段。
- 采集截屏、进程、日志和`/data`可用空间；不要将手机号、token、短信、付费订单或原版商业素材提交 Git 公共仓库。

## 阶段 A：纯本地会话与主菜单

- [ ] 原版初始化回调实际执行：确认 `TWPurchase.Native_SDKInitEnd` 与 `Native_SDKLoginEnd` 的动态命中、真实参数类型与受影响状态。
- [ ] 识别游戏使用的玩家结构，明确 `String` 代表何种数据、`int` 对应何种状态（不同于假定在线认证成功）。
- [ ] 本地单机模式产生独立本地玩家记录；不创建对真实拓维服务器有效的 token。
- [ ] 手机登录页面不遮挡游戏，无真实联网账号/短信要求。
- [ ] **实际进入原版主菜单或地图**，记录截图与游戏进程仍在前台。
- [ ] 完整断网下多次冷启动仍可回到主菜单。

## 阶段 B：第一关

- [ ] 实际显示可选的原始第一关 `LevelDefinition`，记录实际关卡 ID（不预填未经确认的编号）。
- [ ] 飞行模式点击并进入关卡，确认正常渲染背景、植物、僵尸和动画。
- [ ] 操作或完成关卡；胜利/失败画面均真实记录。
- [ ] 区分选关前、开始前、结算后三个可能的网络请求，不把任何通用请求默认视为关卡必需。
- [ ] 不向原版服务器发送账户、付费或游戏进度数据。

## 阶段 C：结算、本地状态写入

- [ ] 真实结算回调与原生玩家对象字段已经定位。
- [ ] 读取真实游戏存档路径：先从 `AndroidGameApp.GetUserDataFolder`、`Resources_GetUserDataFolder` 追踪文件，不能假定该国服版本必然用 `pp.dat`。
- [ ] 结算前和结算后对比存档文件名称、大小、SHA256、修改时间，再逐字段分析进度/星级等；不要把时间戳变化当成完成关卡的证据。
- [ ] 离线玩家状态事务性写入，幂等处理重复结算；不得覆盖真实联网账号档案，也不生成在线货币/付费权限。

## 阶段 D：冷启动读档

- [ ] 通过 `adb shell am force-stop` 真实结束进程。
- [ ] 不清空 app data，仍保持飞行模式，再启动相同测试 APK。
- [ ] 原版主菜单可进入，第一关完成/解锁状态确实保持；提供同一关卡前后截图和本地存档差异。
- [ ] 再进行第二次重启，结果一致；不存在多次发奖或档案回退。
- [ ] 如果存在文件损坏/版本迁移，必须提供明确回滚/恢复流程。

## 每次测试的最小证据记录

| 字段 | 记录内容 |

| APK SHA256 / commit / 原生 ELF BuildID | 全部真实值 |
