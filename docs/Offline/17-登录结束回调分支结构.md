# TWPurchase 登录结束回调的真实分支检查

经 [真实调用链 #42337879073](https://github.com/969981/PVZ2_Resources/actions/runs/42337879073) 验证：

- `TWPurchase.run()` → `TwOfflineSDK.init(...)`，随后 `Native_SDKInitEnd`、`Native_SDKLoginStart`；
- `TwOfflineSDK.login(...)` 的 `onResponse` 包含 5 个 `Native_SDKLoginEnd` 调用站点，位于反编译文件行 **169/173/177/180/185**；
- 原始 JNI 声明 `void Native_SDKLoginEnd(long,int,String)`；
- 手机登录界面按 Android BACK 后仍不消失，且无游客入口的证据来自 [模拟器 #42335037684](https://github.com/969981/PVZ2_Resources/actions/runs/42335037684)。

后续已确认实际参数来源见下方“2026-11-07 真实参数证据”。`int` 的**数值**虽已核实为 0/1，但**业务语义**仍不能直接判定；`String` 确认为 `loginResultBean.token` 的字段引用，令牌值及原生层处理尚未验证。不能自行把其中一个值当作无需服务端验证的离线成功码。

为了进一步精确定位，本仓库增加 `scripts/offline/twpurchase_login_branches.py`，它只在**私有的 JADX 源码树**中提取对应 5 个位置的：

- 调用原始源码行号和形参数量；
- 三个参数表达式的抽象类别（变量、整数、字符串、成员字段、方法调用等）；
- 附近少量 `if` 数字比较的**候选常量**（不解释含义）；
- 原始源码文件 SHA256，方便和同一 APK Build 关联。

生成元数据 `twpurchase_login_end_branch_shapes.csv` / `twpurchase_login_end_branch_summary.json` 不含实际账号、token、字符串字面量、原版函数体或游戏文件。

下一层必须在与源 SHA 对应的模拟器里记录回调实际被触发的分支；再通过 Ghidra/注册表验证 JNI 入口，从而为**独立本地单机会话**设计确定的数据合同。原版关卡进入、结算与重新打开后的存档读回仍未验证，不等于离线 APK 已完成。

参见 [[15-登录返回键与JNI边界实测]] · [[16-JNI注册表函数映射]]。

## 2026-11-07：五个 Java 调用真实参数已确认

[Actions #42339491204](https://github.com/969981/PVZ2_Resources/actions/runs/42339491204) 通过源 APK SHA256 校验、JADX 反编译和新增的只导出字段**名称**与小整数的脚本，得到以下同构建静态记录：

| 调用位置 | 第 1 参数（原生句柄） | 第 2 参数（整数） | 第 3 参数（传入 JNI 的 Java 字段） |
| --- | --- | --- | --- |
| `TWPurchase.java:169` | `TWPurchase.this.mNativeDriverPtr` | `0` | `loginResultBean.token` |
| `TWPurchase.java:173` | 同上 | `1` | 同上 |
| `TWPurchase.java:177` | 同上 | `1` | 同上 |
| `TWPurchase.java:180` | 同上 | `1` | 同上 |
| `TWPurchase.java:185` | 同上 | `0` | 同上 |

原版 `com.talkweb.twOfflineSdk.bean.LoginResultBean` 同时有 `code:int`、`nickName:String`、`token:String`、`userId:String`。这里经过**源代码参数位置**校验，确认第三个参数不是直接使用 `userId`，也不代表令牌就是游戏存档身份。

**重点**：`0` 或 `1` 目前只知道是传给原生函数的 Java 字面量，并不等于已经验证了原生成功分支、已认证用户状态或可在断网时伪造的合法令牌。原生参数消费继续见 [[20-原生登录状态与玩家数据消费核验]]。
