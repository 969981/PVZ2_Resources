# `libSrc.so` 原生字符串到 ARM64 指令引用的定位

## 原始证据

[真实 APK 代码审计 #42332859550](https://github.com/969981/PVZ2_Resources/actions/runs/42332859550) 已确认同 SHA256 的国服 4.2.8 可提取 **6 个 DEX 与 28 个原生 SO**，并产生 3,695 条原生字符串索引、1,356 条 DEX 字符串索引（包括与目标无关的第三方 SDK 字符串）。Java 反编译在该轮单独报错，已修复诊断与打包重试，见 [[10-全代码反编译与离线检查点]]。

以下字符串的来源是 ARM64 `libSrc.so` 的静态内容，而非已证明执行的请求：

| 原始字符串中的域名 | 字符串起始文件偏移 / ELF VA | 可能需要研究的用途（未证实） |
| --- | --- | --- |
| `pvz2cdn.ditwan.cn` | `0x16050D1` | 资源更新或下载 |
| `cloudpvz2androidbeta.ditwan.cn` | `0x165DF7F` | 游戏云接口（测试域名） |
| `cloudpvz2android.ditwan.cn` | `0x16AA69D` | 游戏云接口 |

这里给出的文件偏移与 ELF 映射地址在这一份真实 ARM64 文件中相同，但不应推广至其他构建。**这些不是函数入口，也不是可直接 Hook 的位置。**

## 静态指令交叉引用

新增 `scripts/offline/arm64_xrefs.py`：

- 只读取 SHA256 严格匹配的 APK 和 `lib/arm64-v8a/libSrc.so`。
- 读取 ELF64 `PT_LOAD` 执行权限分段，扫描 `ADR` 或 `ADRP + ADD` 形成原生字符串地址的指令。
- 将指令地址与字符串地址关联到 `arm64_url_string_xrefs.csv`；只保存域名、RVA、指令模式。
- 由 `.github/workflows/pvz2-offline-arm64-xrefs.yml` 在独立临时环境跑真实数据，保留 7 天衍生索引 Artifact；不上传商业 SO 或原 APK。

该模式**不能覆盖**通过 `LDR` 常量池、GOT、虚函数、哈希域名构造、加密字符串或动态 JNI 桥接形成的引用。因此“未找到”不代表没有调用。

## 下一步怎么验证真正的网络分支？

1. 用与来源 APK 完全一致的 `libSrc.so` 在 Ghidra 中载入，导航到 `native_literal_rva_hex`。
2. 从字符串的静态 XREF 追踪到 `code_reference_rva_hex` 指令附近的实际函数，再看它调用什么 `curl`/socket/Java 方法。
3. 使用同构建 Android 模拟器，在飞行模式下通过 GDB/Frida（仅限个人测试）观察这个**函数是否执行**、在启动/选关/结算的哪一步执行，以及参数与返回值。
4. 对“可选联网”进行**本地空操作/缓存回退**；对真正需要远程状态的功能设计事务性本地存储和数据合同。不能把所有 API 改成返回 HTTP 200，否则会破坏游戏状态一致性。
5. 实际补丁必须有原字节校验、构建 ID、可回滚和“启动→关卡→结算→重启读档”完整回归。

不模拟支付订单和线上账号权益；不公开上传原版 ELF、解包资源或 APK。
