# 启动与网络依赖

## 第一步：验证输入安装包

本仓库原始研究记录的 APK SHA256：

`64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4`

Package 候选：`com.popcap.pvz2cthdbk`，来自 Android 资源观察，**不是**已核验的 Binary Manifest 输出。运行时必须通过 `aapt2 dump badging`、`adb shell pm path` 和 `dumpsys package` 再确认。实际 `versionCode` 未知，不得编造。

在仓库根目录执行：

~~~powershell
python scripts/offline/audit_apk.py "X:\ROMS\Android\PVZ2\PVZ2_4.2.8\PVZ2_4.2.8.apk" --out audit/local/offline/4.2.8
python -m unittest discover -s tests -v
~~~

`static_audit.json` 报告 ABI、DEX、SO、Manifest 原始类型、可选 aapt2 版本与主机候选；`candidate_hosts.csv` 只保留域名及出现次数，不记录带 token 的完整 URL。该扫描默认每个 DEX/SO 只读取前 8 MiB，可能遗漏隐藏、分段、加密或动态构造的主机名。若需扩大覆盖，可增加 `--scan-mib 64`；仍只属于**静态字符串候选**。

## 第二步：取证前准备

1. 用经授权的原版安装包在测试 Android 设备/模拟器安装游戏，使用独立测试存档。
2. 用 `adb devices` 确认设备在线，启用飞行模式，观察启动界面并记录能否继续进入主界面。
3. 保留原 APK、签名与存档备份；不要直接覆盖个人常用安装版本。
4. `adb logcat` 可能包含无关应用日志和敏感内容，所有原始日志只在本地保存，不上传到公共仓库。

~~~powershell
python scripts/offline/collect_adb_evidence.py --launch --seconds 45 --out audit/local/offline/runs
~~~

该脚本首先要求 `airplane_mode_on=1`，不自动更改系统网络设置。仅在自有/授权环境需要对照联网启动时使用 `--allow-network`。允许通过 `--serial DEVICE_ID` 选设备，但**设备编号不写进结果 JSON**。

## 第三步：分类服务调用

每个可复现事件单独记录：

| 维度 | 待采集数据 |
| --- | --- |
| APK 版本 | SHA256、包名、versionName、versionCode、ABI |
| 触发条件 | 首次启动/重复启动/进入世界/关卡结束/读档 |
| 网络症状 | 等待、超时、弹窗、崩溃、静默降级 |
| 代码证据 | Java 调用点 / native 调用点 / 返回值；标注真实 Build |
| 本地状态 | 变更前后存档与配置的差异（仅本地保存） |
| 单机决策 | 非必要→安全降级；必要→设计本地合同；线上付费/账户→不仿造 |
| 证据等级 | 静态字符串 / 代码推断 / 真实日志 / 已重现实机 |

只有实际采集到数据后才能填入对应事件、目标主机和方法；现在不能宣称登录、登录检测或资源下载的补丁地址已找到。

## M1 成功门槛

飞行模式下重复启动，记录真实 UI 截图/观察、logcat、Android 包版本与测试时间，至少给出 **首次安装**、**联网初始化后断网**、**完成一局后重启** 三种独立结果。若只能观察到卡在登录页，则归类为失败/待逆向，不得把它写成离线验证通过。
