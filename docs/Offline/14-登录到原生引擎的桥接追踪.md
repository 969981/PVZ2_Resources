# 从拓维登录回调追到原生游戏入口

## 来自原始 APK 的已确认方法结构

[真实 JADX 分析 #42334335971](https://github.com/969981/PVZ2_Resources/actions/runs/42334335971) 在原版 APK 中读取到 18 个目标 Java 类的 597 条候选方法，均保留原始源码 SHA256 和行号。属于静态 Java 方法/调用结构，**不是模拟器中实际执行的调用日志**。

### 拓维 SDK 登录链

- `com.tw.gamesdk.core.GameSDK.login` (源反编译行 139)：候选 `autoLogin`、`checkAutoLogin`、`showLoginUI`、`loginCallback.onFailure`。
- `GameSDK.showLoginUI` (行 179)：调用 `TwPay.loginSdk`，并出现 `loginCallback.onSuccess/onFailure` 回调。
- `GameSDK.autoLogin` (行 194)：调用 `TwPay.loginQuickSdk`、`TokenUtils.refreshToken`、`getUserInfo`，涉及本机已存用户状态。
- `com.tw.gamesdk.ui.TwGameLoginUtil.performLogin` (行 441)：实际代码引用 `RequestUtils.twgameLogin`；`RequestUtils.twgameLogin` (行 53) 引用 `OkHttpClientNet.okHttpPost`。
- `GameSDK.saveUserInfo` (行 292)：调用 `UserDataManager.getInstance` 并写入 `SharedPreferences`；`UserDataManager.setCurrentUser` 和 `saveToPreferences` 也保存本地账号管理数据。**这些是在线 SDK 的本机用户缓存，不等于可单机启动的玩家数据。**

### 原生游戏生命周期

- `com.popcap.pvz2cthddev.SexyAppFrameworkActivity.onCreate` (行 389) 创建 `AndroidGameApp`。
- `AndroidGameApp` 构造函数 (行 148) 调用 `Native_GameAppInitialize`；`onActivityStart` (行 175) 调用 `Native_applicationDidFinishLaunching`。
- `AndroidGameApp` 同时声明 `Native_applicationDidBecomeActive` 等 JNI 生命周期入口。
- `AndroidGameApp.Resources_GetUserDataFolder` 和 `GetUserDataFolder` 返回 app internal/external 目录；它们是**真实存档文件定位入口**，但还没有得到游戏存档字段。
- `AndroidGameApp.UploadTracking` 调用 `TwOfflineSDK.uploadTracking`，提示游戏本身也间接使用另一套拓维 SDK；不能只检查 `GameSDK.login`。
- `TwGameSDKImpl.initGame`、`TwGameSDK.init` 属于另一组广告/资源 SDK 初始化，需要与主认证回调区分。

## 本轮新增的入站引用工具

`scripts/offline/bridge_site_index.py` 读取一次性私有 JADX 输出，对整个 `com/popcap`、`com/tw`、`com/talkweb` Java 树交叉索引：

- `GameSDK.getInstance`、`TwPay.loginSdk`、`RequestUtils.twgameLogin`
- `loginCallback.onSuccess/onFailure`、`LoginStateListener`、`UserDataManager`
- `TwOfflineSDK` 与 `TwGameSDK` 相关调用
- `AndroidGameApp`、`Native_GameAppInitialize`、`Native_applicationDidFinishLaunching`

产物 `login_game_jni_bridge_sites.csv` 只存 class path、源行号、方法名提示、固定事件标签及文件 SHA256；**不含游戏原始源码、函数体、登录参数、token 或支付数据**。与 `first_party_login_methods.csv` 联合，可以优先定位 PopCap/SDK 混合调用点。它仍不等于运行时确证。

## 可落地的单机集成次序

1. **验证登录弹窗关闭方式**：用 `login_back_probe.py` 在实机化模拟器中确认拓维账号 UI 是否允许安全返回到原生游戏菜单，避免盲目改二进制。
2. **闭合 SDK → 引擎桥接**：在完整私有 JADX 树核对所有 `loginCallback.onSuccess` 的调用者和用户对象，在同 SHA Native 侧确认是否收到字段。必须知道回调参数类型、是否异步、主线程限制。
3. **独立本地档案**：`Offline/adapter/java/org/pvz2/offline/LocalProfileStore.java` 已有纯本地 UUID、原子写盘、幂等关卡完成和读档测试。需要改造为游戏真实字段后才能接入，不使用真实联网身份。
4. **关卡完成对账**：真正进入第一关后，先记录正式存档位置与玩家状态字段，再接入进度；不能仅写一个外部 JSON 就称为“游戏存档可用”。
5. **全程断网验收**：首次安装 → 主界面 → 关卡进入 → 胜利/失败 → 退出重启 → 进度/植物/解锁保持。没有真实截图与读回证据的项一律标记未完成。

## 证据边界

当前已证实：本地资源解压完成、出现拓维手机登录界面；SDK 和 JNI 生命周期分别存在。**尚未证明 GameSDK 的具体成功回调如何投递给 Native 引擎，也未证明关卡进入是否再次联网。**
