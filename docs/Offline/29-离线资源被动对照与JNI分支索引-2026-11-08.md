# 原版离线加载的被动对照与 JNI 上游分支追踪

> [!warning] 研究状态
> 这轮只提交研究工具和 CI 实验设计；尚未从本轮新流程获取实际 Android 运行结果。**不能声称已恢复主菜单、第一关或原版存档。**

## 1. 为什么增加被动对照

此前 [Actions #42383797764](https://github.com/969981/PVZ2_Resources/actions/runs/42383797764) 在原始签名未改的 APK 上观察到：120 秒存活、420 秒资源加载 20%、720 秒仍显示相同画面 SHA。没有盗版警告，但未能进入主菜单。

该实验加载了 `frida_original_local_session_trial.js`，其 `TWPurchase$1.run()` Hook 会替代原始 Runnable，依序同步请求四个 JNI 回调。这与原版 `TwOfflineSDK.init` / `login` 异步协议不同，故“原版 APK 字节未被修改”**不等于**“原版启动流程未被修改”。

## 2. 两种模式（不同实验，绝不混称）

| 模式 | 入口 | 原版 APK SHA | 运行时方法替换 | 意义 |
|---|---|---|---|---|
| `passive-observer`（CI 默认） | `passive_original_observation.py` + `frida_original_resource_observer.js` | 必须与 `64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4` 相同 | 无 TWPurchase/Login/SDK 方法替换；仅被动读取 Splash 字段 | 原版飞行模式加载对照 |
| `jni-trial`（仅手动指定） | `original_signed_session_trial.py` + `frida_original_local_session_trial.js` | 同上 | 有：替换 `TWPurchase$1.run()`，模拟本地回调时序 | 仅实验回调变化，不是已验证本地登录 |

默认推送运行 `.github/workflows/pvz2-offline-original-signed-local-trial.yml`。手动 `workflow_dispatch` 可指定 `mode=jni-trial`。执行器仍是 Android 11 x86_64 + ARM Native Bridge，因此原版加载慢、卡顿或不匹配，不足以推断 ARM64 真机表现。

## 3. 采集与结果解释

- 只采集 `mCurrentDecompressStage`、`mLeftDecompressTime`、`mIsFirstInit` 可读取的非敏感状态值；不能把 `mCurrentDecompressStage` 数字未经验证等价为百分比。
- Frida 明确产生 `TRACE_HOOKS_INSTALLED` 后，才可说只读脚本已加载；仅 `frida_status=attached` 不等于 Hook/采样成功。
- 若字段不存在，记录 `TRACE_HOOK_ERROR`，不以空值冒充“进度为零”。
- `original_signed_trial.json` 记录 `experiment_mode` 和 `observer`；`acceptance.json` 仍将 `main_menu_accepted`、`level_1_accepted` 和 `offline_playable_accepted` 标为 `false`，直到有独立实机验证。
- 相同屏幕截图只说明两个采样时刻画面一致；不是原生线程死锁的单独证据。DNS 失败计数只是相关性线索，不是因果结论。

## 4. 原生上游判断的静态索引

[Actions #42380912254](https://github.com/969981/PVZ2_Resources/actions/runs/42380912254) 的上一版产物仅确认注册指针 `0x05722FF0` 位于 `FUN_057227F0` 的函数体内，函数有 44 个静态被调用函数、1 个静态调用者 `FUN_0568D380`；未产出完整的 `surface_branch_index.csv`。

新增 `PvZ2SurfaceBranchIndex.java` 处理：
1. JNI 注册指针对应位置所在函数的条件分支与调用位置；
2. 最多 8 个单层静态调用者的条件分支与调用位置；
3. 输出每行 `scope` 区分 `JNI_CONTAINING_FUNCTION` 和 `ONE_HOP_STATIC_CALLER`；
4. `last_callsite` 仅是线性地址顺序中最近的上一个调用，**不是已验证的控制流前驱**；
5. `rank_surface_branch_candidates.py` 仅作静态候选优先级排序，保留 `actual_signature_or_login_branch_verified=false` 和 `playability_verified=false`。

> [!note] 不要盲目改写
> `0x05722FF0` 不是已证实函数入口或补丁地址；`FUN_0568D380` 也不等于已确认完整性检查函数。必须先用真实运行时 PC/LR、模块加载基址与两个 JNI 回调的非敏感原生回溯交叉验证，再定位分支条件。

## 5. 后续决策

- **被动对照也停在资源加载**：先核对资源解包/校验进度、网络失败时序和 ARM Native Bridge 的性能影响；保持签名验证线独立。
- **被动对照能继续，但 JNI 实验停滞**：优先检查四个 JNI 回调的状态顺序、生命周期和原始异步回调，不再同步模拟整个登录链。
- **仅重签名版本出现正版警告/退出**：对比原版和重签版的原生实际调用时序，而非仅以静态分支距离决定要改哪处。
- **未出现主菜单/第一关/冷启动保存证据**：持续标记 `offline_playable=false`。

## 6. 开源交付边界

开源自主编写的 Frida/Ghidra 探针、原版 APK SHA 锁定的本地实验脚本、数据脱敏的研究结论及测试。不要发布原版/重签 APK、完整商业 Smali、`libSrc.so`、原版游戏素材、签名密钥；让使用者对其合法获取的本地 APK 自行运行构建。
