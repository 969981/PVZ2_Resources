# 原版 SDK 异步登录时序：独立实验

> **结论边界：**这份提交新增的是原版签名 APK 的 Frida 生命周期观测，不是离线登录修复，也不是可玩 APK。尚未获得本次新 Actions 的真实实验 JSON，不声称主菜单、第一关、存档已通过。

## 1. Smali 原始调用关系（已核对类与方法签名）

\`\`\`text
TWPurchase.InitializeSDK(String)
  -> TWPurchase$1.run()
  -> TWPurchase.Native_SDKInitStart(long)
  -> TwOfflineSDK.init(Activity, appId, callback)
     [异步] TWPurchase$1$1.onResponse(int, String)
       InitResultBean.code 4000 -> Native_SDKInitEnd(handle, 0)
                              -> Native_SDKLoginStart(handle)
                              -> TwOfflineSDK.login(Activity, callback)
         [异步] TWPurchase$1$1$1.onResponse(int, String)
           LoginResultBean.code 3000 -> Native_SDKLoginEnd(handle, 0, token)
           LoginResultBean.code 3006 -> Native_SDKLoginEnd(handle, 0, token) [游客]
           LoginResultBean.code 3001/3002/其他 -> Native_SDKLoginEnd(handle, 1, token)
       InitResultBean.code 4001 -> Native_SDKInitEnd(handle, 1)
\`\`\`

上述 code 是经解析 JSON Bean 得到的业务码，并非 SDK 回调 onResponse() 的第一个 int 参数。**不能将两者混淆**。\`token\` 与 \`userId\` 都属于敏感账户数据；公开 CI 不采集、导出或比较其内容。

## 2. 避免 A/B 对照互相污染

- **被动对照 \`passive-observer\`：**继续使用未修改的 \`frida_original_resource_observer.js\`，只读取已有 Splash 的可用数值字段；不包装登录或 SDK 方法。
- **时序实验 \`lifecycle-observer\`：**新增 \`frida_original_sdk_lifecycle_probe.js\`，包装 10 个已确认的方法，仅记录方法进入/正常返回/异常、相对毫秒数、两个 JNI End 参数中的小范围整数状态码；每个原方法只调用一次，原样返回或抛出异常。
- 方法包装即使不主动篡改返回值，也可能影响调度；因此**绝不把 \`lifecycle-observer\` 的结果冒称为无侵入的原版对照**。
- **旧 \`jni-trial\`：**保留为显式实验，替换 TWPurchase$1.run 并人为组织同步 JNI；不能作为正常异步登录可行性的证据。

## 3. 证据采集与防泄漏

\`consent_probe.py\` 在点击隐私条款“同意”前按 Android PID 附加 Frida；仅接受固定方法名、\`ENTER/RETURN/THROW\`、相对时间及 \`JNI_INIT_END/JNI_LOGIN_END\` 整数状态码。不会采集回调 JSON、手机号、令牌、玩家 UID、证书、签名数据、原始二进制、支付订单或完整 Java 堆对象。

新增合成测试拒绝畸形类型，禁止将请求参数中夹带的 token/userId 透传到报告。检查报告 \`sdk_lifecycle_hooks_installed\` 和 \`sdk_lifecycle_event_count\`，但它们仅证明观测工具有效，**不能证明玩家已登录或游戏可玩**。

## 4. CI 实验

- workflow: \`.github/workflows/pvz2-offline-sdk-lifecycle.yml\`（独立 Actions，不覆盖被动对照）
- mode: \`lifecycle-observer\`
- 原始 APK SHA256: \`64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4\`
- Android 11 / x86_64 + Native Bridge、飞行模式、条款确认、5/120/420/600 秒观察
- Artifacts：\`pvz2-original-signed-sdk-lifecycle\`；仅脱敏 JSON 与屏幕取证，保留 2 天。
- CI 只有在原版进程存活、Frida 附加且确实采到至少一条生命周期事件时通过观测门控；即便通过，\`offline_playable_accepted\` 仍是 \`false\`。

## 5. 如何解读新的结果

| 事件序列 | 能证明什么 | 还不能证明什么 |
|---|---|---|
| \`JNI_INIT_START -> SDK_INIT -> INIT_CALLBACK -> JNI_INIT_END\` | Java SDK 初始化回调发生且到达 JNI | 原生状态机完成初始化 |
| 发生 \`SDK_LOGIN\`、未发生 \`LOGIN_CALLBACK\` | 登录已发起、观察窗口内未见回调 | 永久死锁、网络不可修复 |
| \`LOGIN_CALLBACK -> JNI_LOGIN_END(status=0)\` | 原版 Java 将状态 0 交给 JNI | 用户令牌有效、原生玩家资料可用 |
| \`JNI_LOGIN_END(status=1)\` | Java 告知原生登录失败 | 可以通过伪造状态 0 让游戏稳定加载 |
| 停留手机号登录 UI | 真实离线阻碍包含登录交互 | 已完全解析原生依赖或存档 |

## 6. 必须保留的最终验收

1. 仅在离线/无账号环境下验证本地玩家状态的合法、稳定初始化，不把“接受了回调”当作“玩家有效”。
2. 完整进入可操作主菜单；实际完成第一关并结算，记录脱敏截图与进度。
3. 强制停止后冷启动，原生引擎从本地进度读取相同关卡状态。
4. 以上未通过前，不发布标记为“离线可玩”的 APK。开源自行编写的工具、可复现实验流程和测试；避免分发无授权的商业游戏包、原始 SO、反编译游戏代码或付费素材。

支付模拟 \`offline_iap_mock.py\` 仍仅适用于 \`test.pvz2.*\` 合成商品，不产生真实商店交易或游戏付费权益，不能替代上述主线验收。
