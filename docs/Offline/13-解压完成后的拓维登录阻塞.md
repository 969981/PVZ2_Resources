# 国服 4.2.8 解压完成后的真正阻塞：手机账号登录

> [!important] 目前不能进入主界面
> 真实 Android 11 / API30（ARM 转译）模拟器在飞行模式下完成了初次隐私授权、本地资源解压，并停留在拓维游戏登录界面。**当前阻塞点是账号初始化 UI，而非已经证明的关卡联网检查。**

## 真实离线运行时证据

[Actions #42332127813](https://github.com/969981/PVZ2_Resources/actions/runs/42332127813) 已完整成功，使用源 APK SHA256 `64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4`。截图和元数据由短期 Artifact `pvz2-chn428-offline-extraction-monitor` 提供，不将商业游戏图片写入 Git。

| 授权后运行时间 | 实测状态 | 数据分区占用 | 剩余空间 |
| --- | --- | --- | --- |
| 120 秒 | 游戏自身“解压文件 1/6”画面，当前条约 42% | 3,469,604 KiB | 12,720,816 KiB |
| 300 秒 | 解压中，当前条约 99% | 4,387,556 KiB | 11,802,864 KiB |
| 600 秒 | **拓维游戏手机号码登录页面**，游戏仍在前台 | 4,387,660 KiB | 11,802,760 KiB |
| 900 秒 | **同一登录页面**，像素 SHA 与 600 秒相同 | 4,387,660 KiB | 11,802,760 KiB |

全程 `airplane_mode=1`，无 Java FATAL / Native Fatal signal / linker 错误；采样日志中出现 19 条 DNS 失败和 1 条连接失败。**这些日志计数不能在未保存调用主机、堆栈和时刻的情况下归属给某一条登录调用。**

900 秒时 Android UIAutomator（27 节点）真实识别到：

- 顶部：拓维游戏标识（`TV`）与 `官网`。
- `+86`，`请输入手机号注册/登录`，`一键登录`。
- `请输入短信验证码`、`获取验证码`、`登录`。
- `账号密码登录`。
- `已阅读并同意`、`《用户协议》` 与 `《隐私政策》`。

未发现本界面有 `游客登录`、`跳过` 或直接进入游戏的可见入口。所有可见登录形式都关联手机、验证码或账号，不应伪造真实短信或在线身份。

**新判断**：解压可以在未联网情况下进行、约 600 秒进入账号 UI；但在该 UI 未进入游戏，因此**尚无证据证明进入或完成关卡时具体执行哪个联网函数**。

## 下一步改造目标（不是已完成）

1. **单机入口**：先从 GameSDK 的真实 initialize/login 成功回调和用户数据结构中明确哪些字段会传给游戏引擎；提供`LocalOfflineProfile` 或本地用户入口，不发送网络请求、没有真实账号权益。
2. **保留玩法引擎**：使用原版内置的本地关卡配置与资源，在本地用户状态下进入地图与关卡；如原生代码有强制账号关联需通过 GDB/调用链定位独立修改，不能直接把所有网络返回值设为成功。
3. **单机进度**：记录首次进入游戏后的真实存档路径、写入事件及数据结构，建立事务、幂等关卡结算、关闭应用重启后重读；不可模拟支付、真实账号/短信或在线联机结果。
4. **关卡联网检查**：必须实际进入第一关并观察它的资源、登录状态、关卡进入和结算回调，才能确认是否仍需联网；目前没有可靠的关卡联网检查地址或补丁。

实验脚本 `scripts/offline/inspect_login_flow.py` 在已解出的私有 JADX 树中仅导出方法签名/出站调用结构，供下一轮判断 SDK→原生游戏桥接。不能将这些结构索引作为确认已经可用的 patch。
