# 存档与本地状态

## 首要问题：谁是存档权威来源？

原版可能组合本地数据、账户同步与远程校验；必须通过实际调用链和离线读写测试确定，而不能从 `pp.dat`、RTON 等文件名直接推断国服存档位置和数据类型。

初步要核实的行为：新建档案、关卡完成、植物解锁、升级、金币变化、应用关闭、应用重启、版本升级及存档恢复。

## 建议的单机模型（尚非原版事实）

- `profile`：本地档案 ID、离线模式配置、迁移来源。
- `world_progress`：世界/关卡 ID、星级或完成状态、最佳结果。
- `plant_inventory`：植物原始 ID、等级、解锁状态及验证过的相关字段。
- `wallet_local`：仅供单机规则使用的本地货币状态，不对应付费产品。
- `quest_state`：本地任务条件、进度、日期与结果。
- `save_revision`：revision、修改时间、schema、checksum 和备份位置。

以上只是拟议 SQLite 领域表；正式字段以原版存档结构与运行时写入边界为准，不能无证据直接覆盖游戏进度。

## 数据一致性要求

存档应使用事务提交；异常退出不可产生半完成关卡或半扣奖励。迁移需支持 schema_version、先备份、可回滚、原始 ID 不重排；奖励发放具备去重键，防止重启重复结算。每次改动先使用**个人测试副本**做读取-修改-重启对账。

## 验收测试

1. 飞行模式首次建档 → 完成固定关卡 → 正常退出 → 重启，进度保持。
2. 关卡结束时强制结束进程，验证无损坏与可恢复备份。
3. 变更植物状态与本地货币后重启，保证数据一致。
4. 原版在线账户与单机账户严格隔离，不写回在线服务器。
5. 不模拟付费订单、在线权益、排行榜及多人对战结果。
