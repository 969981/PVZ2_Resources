# 从 `LoginResultBean` 到完全本地玩家状态

## 已确认入口

原版国服 4.2.8 DEX 中的 `TWPurchase.Native_SDKLoginEnd` 真正的 Java 签名为：

```java
native void Native_SDKLoginEnd(long nativeContext, int sdkStatus, String sdkResult);
```

这里 `nativeContext`、`sdkStatus`、`sdkResult` 是文档为阅读添加的**解释性参数名**；不能视为原始 Java 参数名或代码中验证的语义。

另有 `TwOfflineSDK.login(Activity, TwOfflineCallback)`；SDK 通过 `CallbackManager.onLoginCallBack(int, String, String, String)` 进行结果处理。ARM64 `libSrc.so` 同一份 Build 的字符串 `Native_SDKLoginEnd` 位于 RVA `0x1654227`，`Native_SDKLoginStart` 位于 `0x15D092C`，`Native_SDKInitEnd` 位于 `0x16F81C3`。这些是**字符串地址，不是机器码入口**。

## 新增模型字段提取

`scripts/offline/login_schema_index.py` 遍历**只在一次性 Actions runner 上存在**的 JADX 源树，搜寻与游戏登录相关的 `LoginResultBean.java`、`TwOfflineCallback.java`、`SimpleUserData.java`、`UserInfo.java` 等类：

- 仅记录类路径、字段名称、字段 Java 类型、源行号和 SHA256；
- 仅记录接口 `onResponse/onSuccess/onFailure` 等方法的**声明类型**；
- 不保存原始方法体、密钥、token 值、登录 JSON、账号信息或商业游戏字节；
- 输出 `login_model_fields.csv`、`login_model_callbacks.csv` 和 `login_model_schema_summary.json`。

**现阶段还不能断言 JSON 结构等同于某一 Java Bean 的字段**：SDK 可能把 Bean 转为 JSON、增加签名字段或者由 Native 另行解析。需对照实际 `TWPurchase.onResponse` 和 Native 数据读取才可以确认。

## 单机玩家状态的正确用法

1. 给单机用户固定、仅本机有效的 ID，禁止送往线上服务；
2. 在原生游戏真正需要的玩家状态结构中保留有效且独立的进度信息；
3. 区分 SDK 会话、渠道/认证、付费权益和本地关卡状态，不将它们一并标成“已登录”；
4. 原生 `pp.dat` 的字段及校验格式必须真实确认；已经实现的 `LocalProfileStore` 只是独立档案和幂等保存测试，暂不是游戏原生存档；
5. 验收仍是断网启动 → 第一个关卡 → 正常结算 → 强制结束进程 → 重启读取同一进度。
