# 构建与验收

当前只交付 M0/M1 分析脚本，没有输出“可玩离线 APK”，因此不应执行任何虚构的 `build-offline.apk` 命令。完成网络/存档原生调用链和原型修改后，单独补构建与签名流水线。

## 预期工具

- Android SDK `adb`、`aapt2`、`apksigner`；必要时 `zipalign`。
- `jadx`、`apktool` 用于 Java/资源阅读及非原始安装包的个人修改测试。
- `Ghidra` 分析相同 APK SHA 的 `lib/arm64-v8a/libSrc.so`；需要实机证据时再选择安全的调试采样技术。
- `Python 3.10+` 与 `uv` 可管理工具环境，但 M0/M1 脚本没有外部 Python 包依赖。
- `WSL/Docker` 可用于静态批处理；Android 运行和 ADB 测试仍需实际设备/模拟器。

## 合格离线版本的门槛

- [ ] 原始 APK SHA 与已审计输入吻合；包名、versionCode、ABI 真实核对。
- [ ] 切断网络的首次启动能进入主界面，无线上账号输入要求。
- [ ] 至少一关完整从选卡进入到结算，游戏不崩溃。
- [ ] 关卡通关保存，结束进程后重新启动，进度一致。
- [ ] 植物升级、金币/钻石、本地关卡解锁各有功能实测证据。
- [ ] 单机任务和商店不依赖真实付费订单；无法移植的活动标记不可用。
- [ ] 签名测试 APK 可独立安装，不覆盖原版私人存档。
- [ ] 公开仓库只提交补丁/源码/文档/合成测试数据，不包含商业素材与 APK。

## 实际测试记录模板

日期 / 设备 / Android 版本 / 源 APK SHA / 已安装包名+版本 / 网络状态 / 复现步骤 / logcat 本地位置 / 结果（PASS、FAIL、BLOCKED） / 崩溃栈与修复 commit。每个可用结论至少重复验证一次，不能用“静态代码可解析”替代真实设备验证。
