# 国服 4.2.8：全 DEX / SO 分析与离线改造路线

## 已验证的输入

源 APK：`PVZ2_4.2.8.apk`，SHA256：

`64b0f2cddb6221baf35fb32d4a0f6e64153428edf5ee5922beddb9726bedbda4`

来自 [[06-M0真实APK审计]] 的真实文件结构：
- 1,374 个 APK ZIP 条目；6 个 DEX；28 个 Android 原生 SO，分别属于 `arm64-v8a` 和 `armeabi-v7a`。
- 核心 `libSrc.so`：ARM64 100,514,400 字节；ARM32 64,808,616 字节。
- 33 个 RSB、2,964 个 RSGP、14,869 个内部资源；原始资源拆包请参阅 [[09-隐私授权后离线解压]] 与 [[versions/CHN/4.2.8-parallel-unpack-results]]。

**重要区别**：资源解包不是程序反编译；DEX 可以反编译为近似 Java，而 `libSrc.so` 是 ELF 机器码，不能凭 JADX 恢复游戏原始 C++。原生行为必须继续用 ARM64 指令、字符串交叉引用和运行时证据验证。

## 已落地的自动化

1. `scripts/offline/reverse_dependencies.py` 从原始、校验后的 APK 提取全部 `classes*.dex` 与 `lib/arm64-v8a/*.so` / `lib/armeabi-v7a/*.so`。
2. 可选调用 **JADX 1.5.6** 反编译六个 DEX，生成私有 `scratch/jadx/sources/` 全量 Java 工作树。
3. 枚举 Java 的候选方法、源文件路径、行号、源码 SHA256；同时分析 DEX 字符串索引和 ELF PT_LOAD 映射，给出 SO 字符串的文件偏移与虚拟地址。
4. 候选分类：`STARTUP`、`NETWORK`、`ACCOUNT`、`RESOURCE`、`LEVEL`、`SAVE`；`COMMERCE_EXCLUDED` 单独列出，禁止将支付或在线付费资格冒充离线成功。
5. `.github/workflows/pvz2-offline-code-decompile.yml` 在 GitHub Actions 还原 88 分卷、校验 SHA256 并执行该审计。只有提取结果/分析索引（JSON/CSV）作为短期 Artifact 保存，源码和游戏 SO 不公开提交。

生成的元数据：

| 文件 | 用途 |
| --- | --- |
| `reverse_report.json` | 输入、文件数量、JADX 状态、各类候选分布和边界 |
| `source_members.csv` | 6 DEX + 28 SO 的路径、字节数、SHA256 |
| `java_callsite_cues.csv` | 近似 Java 方法、行号、分类、源码校验哈希 |
| `dex_string_cues.csv` | DEX 中候选字符串的索引与偏移；不上传带凭据的 URL |
| `native_string_cues.csv` | SO 中候选字符串文件偏移 / ELF 地址，仅作交叉引用入口 |

**地址语义**：`native_string_cues.csv` 的 `elf_rva_hex` 是字符串位置，不是代码分支地址或 Hook 地址。必须在 Ghidra 中对该字符串执行 XREF，再回溯真正读取它的函数，才有代码级证据。

## 本地复现（Windows PowerShell）

先在拥有本项目仓库代码的目录（例如本地克隆的 `PVZ2_Resources`）执行；输入 APK 使用你已有的本地文件：

~~~powershell
$apk = "X:\ROMS\Android\PVZ2\PVZ2_4.2.8\PVZ2_4.2.8.apk"
$research = "X:\ROMS\Android\PVZ2\PVZ2_4.2.8\Research"
$jadx = "$research\tools\jadx\bin\jadx.bat"
python scripts/offline/reverse_dependencies.py `
  --apk $apk `
  --scratch "$research\Decompile" `
  --out "$research\Reports" `
  --jadx $jadx
~~~

若尚未安装 JADX，可从 [官方 JADX releases](https://github.com/skylot/jadx/releases) 下载 CLI，并将其解压在 `Research/tools/jadx`。本地完整 Java 代码位于 `Research/Decompile/jadx/sources/`，原生库位于 `Research/Decompile/original_code/lib/`。两者均留在本机，不纳入公开 Git。

## 离线检查点的真实验收顺序

### 先确认解包完成

[[09-隐私授权后离线解压]] 已证明**飞行模式下**能进入游戏自身“正在解压文件1/6”界面，并且 60 秒到 120 秒进度前进。长时间模拟器任务 `pvz2-offline-extraction-monitor.yml` 用 120 / 300 / 600 / 900 秒截屏和剩余磁盘量明确判定后续进展。不能在其完成前把未观察到的“网络登录失败”当作当前阻塞点。

### 然后追踪三类游戏路径

| 流程 | 真正要定位的点 | 证据要求 |
| --- | --- | --- |
| 首次离线启动 | Android Activity → Java 资源准备 → JNI → Native 主程序 → 世界主界面 | 真实画面、相同 SHA 的 Java/ARM64 调用链 |
| 进入并完成关卡 | 点击关卡 → 关卡 ID/LevelDefinition → 原生战斗 → 结算 → 本地状态写入 | 相同关卡 ID、UI 截图、返回结果、存档前后差异 |
| 退出与重启 | PlayerInfo / 真实 `pp.dat` 候选 → 文件写入 → 重新加载 | 确认真实路径、字段差异、checksum/加密格式、重启一致 |

### 只有证实调用点后才修改

1. 如果是**可选联网**（统计、公告、可选更新），在验证的 Java / Native 调用处安全降级，保留原本的状态与错误处理语义。
2. 如果是**主线玩法必需的云端状态**，先记录本地最小状态合同，独立实现读写和事务恢复，不应直接返回“请求成功”却没有给到所需数据。
3. 若关卡进入/结算在原生 C++ 层，把 Java/DEX 中的网络类全量屏蔽**无法**证明已经离线可玩；需要相同 ELF Build 的函数 XREF 和 GDB 断点。
4. 支付、账号、真实权益验证与线上多人不在单机适配范围内；不会使用假订单或伪造联网账号。
