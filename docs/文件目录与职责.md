## 2. 国服 4.2.8 APK 内部结构（按现有清单）

```text
PVZ2_4.2.8.apk                       # ZIP 容器，共 1,374 个文件项
├── assets/
│   ├── dino.rsb.smf                # RSLB 包装的 RSB 资源容器（实样）
│   ├── init.rsb.smf                # 初始化资源包（按名称判断用途）
│   ├── plant*.rsb.smf              # 植物相关候选资源包
│   ├── zombie*.rsb.smf             # 僵尸相关候选资源包
│   ├── *world*.rsb.smf             # 世界相关候选资源包
│   ├── *.rsb.tag.smf               # 与 RSB 对应的标签/元数据文件
│   └── properties/
│       ├── resourcesDino.rton.smf # 直接 RTON 实例
│       └── *.rton.smf              # 资源配置：18 个
├── lib/
│   ├── arm64-v8a/libSrc.so         # 主要 ARM64 ELF 游戏本地代码
│   └── armeabi-v7a/libSrc.so       # ARM32 对应库
└── ...                             # 其他 ZIP 成员，按原始清单核对
```

| APK 统计（原始 ZIP） | 数值 | 说明 |
|---|---:|---|
| ZIP 文件项 | 1,374 | 不等于解包后资源总数 |
| `assets/*.rsb.smf` | 33 | 实际被展开成 RSB v4 |
| 顶层直接 `*.rton.smf` | 18 | 实测有 RTON magic，可单独转 JSON |
| `*.rsb.tag.smf` | 33 | 已复制保留；具体字段解释待核验 |
| 其他 SMF | 5 | 已原样保留；不可全假设为相同格式 |
| `lib/` 中共享库 | 28 | ZIP 清单数量，不一定都是 `libSrc.so` |

完整的 **每个 APK 成员实际路径/字节大小/CRC** 请用 `scripts/audit/inspect_apk.py` 重建 `apk_filelist.csv`；不要从以上示意树推导出不存在的确定文件名。Android manifest 中的 `versionName/versionCode` 在最初报告时仍待独立验证。

## 3. 解包后的数据流与目录

```text
7z.001 ... .088
    └── 7z x -> 原始 APK (校验 SHA256)
         ├── Stage 0: audit/local/CHN-4.2.8/
         │   ├── apk_audit.json
         │   ├── apk_filelist.csv
         │   └── apk_headers.csv
         ├── Stage 1: Unpack/CHN/4.2.8/stage1/
         │   ├── RSB/*.rsb                       # 33 个
         │   ├── RTON/*.rton                     # 18 个，尚未转换 JSON
         │   ├── SMF-Metadata/...                # 38 个
         │   └── report_probe.json/report_all.json
         ├── Stage 2: Unpack/CHN/4.2.8/stage2/
         │   ├── <rsb-stem>/00000.rsg ...
         │   └── rsg_report.json                 # 2,964 组的溯源索引
         ├── Stage 3: Unpack/CHN/4.2.8/stage3/
         │   └── Resource_Tool 自动产生的各阶段目录
         │       └── *_JSON/                     # 最终转换后的内部资源
         └── Direct RTON: Unpack/CHN/4.2.8/direct-rton/
             └── *_JSON/                         # 18 个直接配置 JSON
```

上面 `Unpack/` 的目录名是**推荐本地输出布局**；GitHub Actions 使用 `$RUNNER_TEMP` 下的临时目录和命名 Artifacts，并未把这些派生二进制文件全部提交到 Git。以实际运行输出和 `*_report.json` 为准；`*_JSON` 是上游 Resource_Tool 生成的目录命名形式，具体中间目录以执行结果为准。

## 4. 文件、输出与证据的对应

| 文件/类别 | 做什么 | 哪一阶段处理 | 主要输出 |
|---|---|---|---|
| `7z.001~.088` | 还原 APK 的连续压缩分卷 | 恢复 | APK |
| `APK` | 游戏分发 ZIP，含资源/本地代码 | Stage 0 | 清单、哈希 |
| `rsb.smf` / `RSLB` | 外层分块 LZMA 容器 | Stage 1 | RSB |
| `RSB` | 资源组清单与字节块容器 | Stage 2 | RSGP |
| `RSGP` / `*.rsg` | 资源组封装 | Stage 3 | 内部成员 |
| `RTON` | 二进制配置对象 | Stage 3 / Direct | JSON |
| `PTX` | 压缩或编码纹理 | 待二次解析 | PNG / atlas（规划） |
| `PAM`、`Reanim` | 动画数据 | 待二次解析 | 结构化轨道/帧（规划） |
| `BNK` | 音频 bank 候选 | 待二次解析 | 索引/音频（规划） |
| `libSrc.so` | 原生游戏逻辑 | 运行时研究 | ARM32/ARM64 函数证据 |

深入理解见 [[资源格式与文件用途]]、[[FORMATS]]；操作步骤见 [[解包操作手册]]。

## 5. 不得混淆的三种“已完成”

- **Git 提交**：脚本、笔记、版本控制的外部工具引用。
- **GitHub Actions Artifacts**：真实解包产生的可下载临时附件，有保留期限。
- **本地 `Unpack/` 文件**：自己重新运行或下载 Artifacts 后才具备的二进制/JSON 数据。

当前实测的 33 个 RSB、2,964 个 RSGP、14,869 个内部文件和 18 个直接 RTON 的来源、分片、成功率详见 [[versions/CHN/4.2.8-parallel-unpack-results]]。
