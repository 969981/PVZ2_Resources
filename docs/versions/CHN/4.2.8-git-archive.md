# Unpack/CHN/V4.2.8 — reproducible Git archives

The request explicitly chose real Git history instead of short-lived Actions artifacts.

**Important:** this GitHub repository is public as verified 2026-11-07. The restored contents include commercial game assets and may be copyright-protected. Review your redistribution permissions and visibility before sharing.

## Why these files are chunked
Three previous runs emitted ~5.9 GB RSB, ~5.9 GB RSGP and ~6.2 GB internal assets/JSON. GitHub disallows blobs of 100 MB or larger; all Git data parts are limited to **64 MiB**. Each original Actions artifact shard is stored as independently compressed tar.zst; source paths are preserved inside the archive and recoverable. This is not Git LFS or a reference to an expiring artifact.

Each shard directory includes **manifest.json**, with original file count, total bytes, archive SHA256, and every part SHA256 and size.

Structure:
~~~
Unpack/CHN/V4.2.8/
  RSB/shard-00/manifest.json + archive.tar.zst.part-000 ...
  RSGP/shard-00/...
  Internal/shard-00/...
~~~

## Restore and verify
~~~
python scripts/archive/restore_git_shard.py Unpack/CHN/V4.2.8/RSB/shard-00 --verify-only --out restored
python scripts/archive/restore_git_shard.py Unpack/CHN/V4.2.8/RSB/shard-00 --out restored/RSB
~~~
Requires tar and zstd. Python first checks sizes and SHA256, then streams the archive through zstd and tar; do not restore untrusted archives. For a complete set, repeat for shard-00 to shard-07 for all three stages.

## Upload workflow
The workflow .github/workflows/git-archive-chn-4.2.8.yml serializes 24 import jobs (8 × 3 stages), each downloading only one known successful artifact, packaging, committing to master and pushing with retries. It does not modify the original ROMS/ tree. If the workflow fails partway through, rerun only missing stage/shard after checking Git history. The repository grows substantially (potentially over 10 GB), which can slow clones and cause GitHub account/repository limits; an appropriate private archive or dedicated release storage is usually more sustainable.

A successful workflow job proves only its Git shard was pushed; check manifests and all 24 expected shard directories before claiming full import.
