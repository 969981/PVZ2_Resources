# PvZ2 CHN v4.2.8 — PTX / PAM / BNK 实测

## 实测通过
- [ASTC PTX 小样本工作流 #42321736104](https://github.com/969981/PVZ2_Resources/actions/runs/42321736104)：从真实 \`dino.rsb\` 中的 5 个 PTX，恢复全局 RSB 表头信息、将 format=161 解释为 Khronos ASTC 5×5、经 astcenc 解码，输出 **5/5 PNG**、校验宽高、错误 0。
- [动画及音频样本工作流 #42321474886](https://github.com/969981/PVZ2_Resources/actions/runs/42321474886)：**PAM → JSON 22/22**；**2 个 Wwise BNK → 22 条 RIFF/WEM**；PTX 部分使用旧 PopStudio 失败，因此这个工作流整体失败，不可误标为成功。PNG 已用单独的成功工作流解决。
- BNK 解析的 DIDX/DATA 偏移均落在合法边界；WEM 是压缩媒体，并非 PCM WAV/OGG。
- PAM 使用固定上游 PopStudio \`a8bd1edd3e1dc4ec79e3b37ee29774e268438d85\` 的命令行 \`180\`，输出结构 JSON；有原始格式差异时审计失败项。
- PTX 格式160/161/162/163 分别为 ASTC 4×4 / 5×5 / 6×6 / 8×8，基础说明参考 [rsb-archive](https://git.littlebell.top/LambdaEd1th/rsb-archive)（许可 AGPL-3.0-or-later）与 Khronos ASTC。使用独立 \`astcenc\`，未复制第三方库源码。

## 批量阶段
- [全部八分片媒体工作流](https://github.com/969981/PVZ2_Resources/actions/workflows/pvz2-media-full.yml) 从第一阶段 33 个 RSB 的八份 Artifact 内读取原始字节，每片经原生解析器提取 PTX/PAM/BNK；PTX 经 astcenc 转 PNG，PAM 经 PopStudio 转 JSON，BNK 拆分 WEM，上传每片审计。
- 成功的完整媒体任务完成后由 [Git 历史归档工作流](https://github.com/969981/PVZ2_Resources/actions/workflows/git-archive-chn-4.2.8-media.yml) 将八个媒体分片转成不超过 64MiB 的 Git 文件和 SHA256 清单，保存在 \`Unpack/CHN/V4.2.8/Media/\`。
- 不把仅提交的 workflow 或未开始的批处理当作实测完成，必须核对 job 结论、每片 \`manifest.json\` 和 JSON 审计。

## 未完项
